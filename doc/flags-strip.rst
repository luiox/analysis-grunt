.. _flags-strip:

flags_strip：伪造访问标志
====================================



形态
----


混淆器给成员和类打上编译器专用的访问标志，制造编译器生成物的假象：

::

   public static /* bridge */ /* synthetic */ Class t() { ... }
   public static /* synthetic */ int Plk;      // 字段池里成千上万条


Java 语义下这些标志各有严格的生产场景：

- ``ACC_BRIDGE`` （0x0040）：javac 只为 **实例方法** 的泛型擦除补齐生成桥接器。static 方法上的 bridge 没有任何编译器会产出。
- ``ACC_SYNTHETIC`` （0x1000）：编译器生成的辅助成员（内部类 ``this$0`` 、枚举 ``$VALUES`` 、nestmates 之前的 ``access$000`` 访问器）。混淆器把它批量打在自己注入的字段池与方法上。

后果：反编译器把标志渲染成注释噪音； ``isSynthetic()``/``isBridge()`` 的反射视图失真；部分框架（按 synthetic 过滤成员的注入器）行为被扰动。


与相邻形态的区别
----------------


- 标志是 **类级元数据** ，不是代码：清理不改任何指令、不改常量池，验证面只有成员访问位本身。
- 标志清理 **不等于** 死成员删除：打了伪 bridge 的方法体照样是活代码，删除是另一个残留的事。
