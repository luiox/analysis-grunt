.. _constant-call:

常量调用（constant call）
======================================


口径：本文件只写 **混淆器会产出什么结构** 。换个输入 jar 仍然成立的内容才写在这里；某个具体样本的取证（哪个类、哪条指令、折叠出什么值）记在仓外研究笔记。



1. 形态
----------


一个本该是字面量的常量，被替换成一次静态方法调用：

::

   <常量 a> <常量 b> ...  invokestatic Owner.helper(desc)Ret


调用点的实参 **全部是常量装载** （ ``iconst_*`` / ``bipush`` / ``sipush`` / ``ldc*`` / ``aconst_null`` ），中间不夹任何计算；被调方法是同 jar 内声明的 ``static`` 方法，方法体是一段直线算术：

::

   iload 0
   ldc <mask>
   ldc <mask2>
   iand
   ixor
   iload 1
   swap
   dup_x1
   iconst_m1
   ixor
   ior
   swap
   iconst_m1
   ixor
   isub
   ireturn


对应的源码形态就是一条 MBA 恒等式，例如 ``(b | ~(a ^ K)) - ~(a ^ K)`` 。常量 ``K`` 与实参 ``a`` 、 ``b`` 由混淆器挑选，使返回值恰好等于原本的字面量。


2. 为什么它是常量
--------------------


三个条件同时成立时，调用点的值与环境无关：

1. **目标纯** ：方法体只做局部变量装载、数值运算、栈整形与返回，没有字段访问、数组访问、方法调用、对象分配、显式抛出。
2. **实参定值** ：所有实参都是常量装载，槽数与描述符严格吻合。
3. **路径确定** ：实参确定 ⇒ 方法内的分支走向确定 ⇒ 执行路径唯一。

于是方法对这批实参的返回值是一个可以离线算出的定值。


3. 常见变体
--------------


.. list-table::
   :header-rows: 1

   * - 维度
     - 观测到的取值
     - 对判据的影响
   * - 实参个数
     - 2–4
     - 无：按描述符算槽数
   * - 实参类型
     - ``int`` 为主，偶见 ``long`` / ``float`` / ``double``
     - 无：求值器按类别分派
   * - 引用形参
     - 调用点传 ``null`` 占位（方法体从不读它）
     - 无： ``aconst_null`` 解成 null 引用
   * - 方法体控制流
     - 直线；偶见单层 ``if``
     - 无：求值器支持分支，按实参定走向
   * - 返回类型
     - ``int`` 为主
     - 无： ``void`` 直接拒绝
   * - 辅助方法命名
     - 随机长串 / 短名
     - 无：判据不看名字
   * - 辅助方法所在类
     - 与被调点同类或异类
     - 无：跨类按容器索引解析


**判据不依赖上表任何一列** ，这是它跨版本稳定的原因。


4. 与相邻形态的区别
----------------------


.. list-table::
   :header-rows: 1

   * - 形态
     - 调用点长相
     - 归属
   * - **常量调用** （本文件）
     - ``常量… ; invokestatic``
     - 本残留
   * - 内联数字混淆
     - ``ldc x ; ldc k ; ixor`` 之类，无调用
     - mjbase ``ConstantFolder``
   * - 字段池化数字
     - ``getstatic arr ; <idx> ; iaload``
     - 需要 ``<clinit>`` 常量传播，另一残留
   * - 字符串解密
     - ``ldc 密文 ; invokestatic decrypt``
     - 另一残留（调用点折叠思路相同，但值域是字符串）



5. 折掉之后
--------------


调用点变成一条常量装载，下游才有东西可折：

- ``常量 == 常量 `` → ``ConstantFolder`` 折成 ``iconst_1/0`` ；
- ``if`` 条件定值 → ``ConstantSwitchFolder`` / 死支删除接手；
- 于是混淆器用恒真谓词 + 死支诱饵搭出来的控制流骨架会塌掉。

本残留 **只负责把调用点变成常量** ，不碰分支与死码，那是下游内置件的职责，分开才能各自单测。
