junk_region_strip：不可达死区 NOP 化（字节级可达性走查）
================================================================================

DecompilerCrasher 家族往方法体里撒两类反工具载荷（账本缺口 #13）：

1. 不可达死区的非法操作码（\ ``0xff``\ impdep2 族）：JVM 校验器只沿可达
   帧走查，加载零失败；javap/CFR/ASM 一类线性走查工具在读到 ``0xff`` 的
   瞬间整体拒载——CFR 因此完全不可用；
2. 死区夹杂在真码之间，从任何分支目标/异常 handler 都进不去。

形态判据来自家族生成面与线上样本实证。fork 全链样本（样本 C）经本 pass
可达性走查实测**无**此残留形态（死区字节 = 0、fail-closed = 0——早期普
查脚本把单字节操作码按 2 字节步进，其"182/251 死区方法"是普查口径伪影，
见台账方法注记），本 pass 面向家族其他样本与上游链产出的死区延续段。


判据
----

字节级可达性走查（**JVM 校验器同款语义**）：worklist = ``{0}`` ∪ 全部异
常表 handler pc，沿操作码精确长度表（含 switch 变长、wide、
multianewarray）展开，分支全部目标入队。可达集合之外的字节段即死区。

保守面（方法整条 fail-closed，字节不动，宁留不猜）：

- 可达 pc 上出现表外操作码（JVM 可加载就不该发生，发生了说明走查口径有
  洞）；
- ``jsr``/``ret``/``jsr_w``\ （动态返回地址，字节级走查跟不了，major ≥ 51
  也不该有）；
- 任何越界目标 / 越界 handler / 空码。


改写
----

死区字节原位写 ``0x00``\ （NOP）：**长度保持**——code_length、全部指令偏
移、StackMapTable 帧、LVT/LNT 行位全部不动，无帧重算面。可达指令一个字
节不碰。改写只发生在死区字节存在的方法上，净类字节零变化。


验证
----

jsoup v3_full 实测（build13 主线 trace）：首轮 24 类 25 站 / 385 字节
NOP 化（fail-closed 348 方法全有计数，宁留）、第二轮 4 站 65 字节，converge
轮维度吸收至 0；\ ``out-of-range=0``。样本 C 复核：死区字节 0（无残留
形态，符合家族分布）。

unittest 8 测试：死区 NOP 化（含异常 handler 路由可达的活码不伤）、
jsr/ret 保守面、表外操作码保守面、干净类零搅动等。与
:ref:`junk-member-strip` 分工：本 pass 只认**可达性**死区（不看成员名
形）；junk 成员层（junk 名形字段/方法链）由 JunkMemberStrip 承载。
